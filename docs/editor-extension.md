# Editor extensions

English | [日本語](editor-extension_ja.md)

Editor extensions are C# code that adapts the editor's behavior to your runtime. They decide things such as what bytes a scene is sent to the runtime as, and how source assets are imported and where they are placed.

[Modules](../Modules) contains example implementations of a runtime and editor extensions, organized as modules. If you use those examples, referencing them is all you need ([DotnetRuntimeSample](../samples/DotnetRuntimeSample/Editor/Editor.targets)). For an example of implementing editor extensions yourself, see [BevyRuntimeSample](../samples/BevyRuntimeSample/Editor).

## How to plug in

The editor project is generated by the Host. All you write is the MSBuild targets file specified by `editorProps` in the project manifest (`*.emptyengine`). The generated project imports this file.

```json
{
    "runtimeCommand": "cargo run",
    "editorProps": "MyGame.Editor.targets"
}
```

```xml
<Project>
  <PropertyGroup>
    <AssetsPath>$(MSBuildThisFileDirectory)Assets</AssetsPath>
  </PropertyGroup>
  <ItemGroup>
    <Compile Include="$(MSBuildThisFileDirectory)Editor/**/*.cs" />
    <PackageReference Include="EmptyEngine.Editor" Version="*" />
  </ItemGroup>
</Project>
```

- The generated project has no default Compile items, so include your editor extension sources explicitly with `Compile`
- At startup, the editor searches all loaded assemblies for implementations of the interfaces below and uses them. No registration code is needed
- Constructor parameters of your implementations are resolved through DI. You can receive `ISchemaSource` (the type catalog) and `ILogger<T>`

Inside the editor, a scene is represented as a tree of `HierarchyNode`, and assets and components as `AuthoringObject`. The main job of an editor extension is converting between these and your runtime's format.

## Required

### Targets declarations

| Item | Description |
|---|---|
| `AssetsPath` | Directory of the source assets. Write it as an absolute path |
| Reference to `EmptyEngine.Editor` | The editor itself |

### Interfaces

Each of the following four needs exactly one implementation. If there is none, or more than one, the editor fails at startup.

| Interface | Role |
|---|---|
| `IHierarchyBlobSerializer` | Converts between the hierarchy state and the bytes exchanged with the runtime. The format matches whatever your runtime defines ([runtime connection protocol](runtime-protocol.md)) |
| `ISceneArtifactStore` | Saves, deletes, and loads subtrees of the hierarchy in a form the runtime can read |
| `IAssetArtifactStore` | Saves, deletes, and loads assets in a form the runtime can read |
| `IDistributionBuilder` | Finishes the distribution output. Writes the list of startup scenes and, if needed, post-processes such as bundling assets. If you don't use distribution builds, an implementation that does nothing is fine |

`ISceneArtifactStore` and `IAssetArtifactStore` must also provide a constructor that takes a `DistributionRoot`.

In a distribution build, after running the command declared by `DistributionBuild`, the editor does the following in order (for builds that specify `DeployBeforeBuild`, this happens in a temporary directory before the command runs).

1. Creates stores for the destination using the constructor that takes `DistributionRoot`, and writes out the scenes and assets reachable from the startup scenes to the destination
2. Calls `IDistributionBuilder.Build`

Writing scenes and assets to the destination is done by the editor; `IDistributionBuilder` is only responsible for the finishing steps afterward. For example, the implementation under Modules bundles the written scenes and assets into a single archive.

### Scene importer

To edit scenes, you need at least one `ISceneImporter` that reads and writes scene source files. Without one, the editor cannot open scenes.

- `SupportedExtensions`: the extensions it handles
- `ImportAsync`: reads a source file and returns a tree of `HierarchyNode`
- `SaveAsync(HierarchyNode, string, ...)`: writes an edited scene back to the source file

If you don't care about the scene source format, just reference the example [EmptyEngine.SceneSource.Editor](../Modules/EmptyEngine.SceneSource.Editor). It is an importer for JSON scenes (`.scene`) that reads and writes using only the type catalog, so it works regardless of your runtime implementation. It also includes importers for nested prefabs, prefab variants (`.variant`), and assets of any type (`.asset`).

### Type catalog

The editor learns the types of component and asset fields from the type catalog (`.artifacts/TypeCatalog.json`). Generate it from your runtime's types as part of the runtime build. The format is JSON Schema ([type catalog](type-catalog.md)). For examples of generating it, see BevyRuntimeSample's [build.rs](../samples/BevyRuntimeSample/build.rs), which builds it from Rust types, and [EmptyEngine.TypeCatalog](../Modules/EmptyEngine.TypeCatalog), which builds it from C# types.

The editor starts without a catalog, but you cannot add components or edit in the inspector.

Asset reference fields only offer assets of the referenced type (`x-target`) as picker candidates. For fields that hold a scene, set `x-target` to the reserved value `@scene`. For example, CatalogTool outputs `AssetReference<IObject>` this way.

## Optional

### Asset importers

| Interface | Role |
|---|---|
| `IAssetImporter` | Imports non-scene source assets (images, audio, etc.). You can implement as many as you like, per extension |
| `IVariantImporter` | Enables creating variants that store only the differences from the original scene |
| `INestedPrefabImporter` | Enables placing another scene as a child inside a scene |

Implementing the following members of `IAssetImporter` adds features.

- `IsSaveSupported` and `SaveAsync`: allows assets edited in the inspector to be written back to the source file
- `AssetImportResult.Dependencies`: keys of other assets the import result depends on. When a dependency is reimported, this asset is reimported too

### Custom inspectors

A Razor component with the `[InspectorFor]` attribute becomes the dedicated inspector for the specified type. Types without one are shown with the default inspector built from the type catalog.

```xml
<RazorComponent Include="$(MSBuildThisFileDirectory)Editor/**/*.razor" />
```

For an example, see BevyRuntimeSample's [BevyTransformInspector.razor](../samples/BevyRuntimeSample/Editor/BevyTransformInspector.razor).

### Targets declarations

| Item | Description |
|---|---|
| `DistributionBuild` | Name of a distribution build and the command to run (`Command`). The output path is passed in as `{output}` |
| `BuildWorkingPath` | Directory in which distribution build commands run. Required if you declare `DistributionBuild` |
| `EditorFrameAncestor` | Origins allowed to embed the editor page. Required when opening the editor with the VS Code extension ([extension README](../vscode-extension/README.md#requirements)) |
